# Security policy

## Reporting a vulnerability

Please report vulnerabilities privately through GitHub: open the repository's **Security** tab and choose **Report a vulnerability**. Don't open a public issue.

Include what you found, how to reproduce it, and what an attacker could do with it. You'll get an acknowledgement within a week, and updates until it's fixed. Once a fix is released, the advisory will credit you unless you prefer otherwise.

## Supported versions

Only the latest release gets security fixes.

| Version | Supported |
|---|---|
| Latest release | yes |
| Older releases and unreleased commits | no |

## Verifying releases

Release archives come with `checksums.txt` and an SPDX SBOM each. The container image `ghcr.io/fernandezvara/backd` is scanned before publishing, carries SBOM and provenance attestations, and is signed with cosign (keyless, GitHub OIDC):

```sh
cosign verify ghcr.io/fernandezvara/backd:v0.9.6 \
  --certificate-identity-regexp '^https://github.com/fernandezvara/backd/\.github/workflows/release\.yml@refs/tags/v' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

Dependencies are watched continuously: `govulncheck` and an image scan run in CI, and Dependabot proposes updates weekly.

In scope:

- **Authentication and sessions** — `/v1/{realm}/_auth`, sessions and API keys.
- **Access rules** — the `rules:` section of `collection.yaml`.
- **Admin API** — `/v1/{realm}/_admin`.
- **Admin web interface** — served at `/_ui/`: its CSP and headers, how it holds the admin token, and any way to run script in it or read that token.
- **CLI** — the commands that use the admin API (`backd login`, `user`, `apikey`, `secret`, `bootstrap`) and the credentials file it keeps.
- **Field keys** — `POST /v1/{realm}/_admin/secrets` with `type: key`, `backd secret create`: a key's value shown more than once or kept outside the sealed store, in a log, an audit record or an error; a function, provider or setting that can read one; a key created, replaced or deleted without a full administrator and a fresh proof; a key deleted while a field uses it; a fingerprint that reveals the key.
- **Audit trail** — `/v1/{realm}/_admin/audit`: records that are missing, alterable, or that contain secrets.
- **User erasure** — `DELETE /v1/{realm}/_admin/users/{id}`: personal data it leaves behind beyond what the docs list, or an erase that skips silently.
- **Encrypted fields** — `fields:` in `collection.yaml`, field keys (`backd secret create`, `/v1/{realm}/_admin/keys`), the stored format and blind indexes, `reveal` rules, `backd encrypt`, and encrypted export and import: plaintext of an encrypted field in the database, a log, an error, an audit record, a job, a remembered answer or an export; a key, data key or blind-index value readable through an API; a value that decrypts in another document, field or realm; a reader who sees a field their `reveal` rule hides; a nonce reused; or a flaw in the format published in the documentation.
- **Server-side functions** — `/v1/{realm}/{database}/_func/…`: the executor, its sandbox and limits, callback credentials and the internal listener, `backd egress` and its per-invocation tokens, a function's ability to reach anything other than what it declares — including over raw TCP or to a private address a declared host name resolves to — and its secrets: `/v1/{realm}/_admin/secrets`, their encryption at rest, and a function's ability to read another database's or realm's.
- **Async jobs** — `/v1/{realm}/{database}/_jobs/{id}`: a job readable by anyone other than its own caller or an API key, or an `Idempotency-Key` claim crossing between two different callers.
- **Email flows and hosted pages** — verification, password reset, address change, invitations: tokens, redirects, answers that tell whether an address is registered; and custom emails a function sends: a message sent to someone the caller shouldn't reach, or past its limits.
- **Files** — `…/_files/…`: uploads in both modes and their tokens, downloads, signed links and the key that signs them, type detection and what a download can run in a browser, the storage credentials, `backd storage reconcile`, and a function's access to files: a file readable, writable or removable by a caller whose rules say otherwise, an object key or header a client can influence, or a secret of the storage in an answer or a log. This includes **public files** (`public: true`, `public_storage:`): a type other than JPEG or PNG, or a picture still carrying metadata, that reaches the public bucket; a name that escapes its key or is renamed to hide its type; a private file written to the public storage, or the public storage's keys able to reach the private bucket; and `url` shown for a file that is not public. That a public file is readable by anyone who has its address, and that a CDN keeps a deleted file until its cache expires, is how the feature works, not a vulnerability.
- **Sign-in with Google, Microsoft or Apple** — `/v1/{realm}/_auth/oauth/…`: a session or login code that can be obtained or redeemed without the provider's proof or the app's PKCE verifier, a `state` or nonce that can be replayed, an ID token accepted that fails its signature, issuer, audience or expiry, an account linked or taken over through a provider address the rules say must not link, a `redirect_to` outside the allowed list, or a request backd makes to a host that is not the provider's.
- **Push notifications** — `/v1/{realm}/_auth/devices`, `/v1/{realm}/_admin/push/*`, the built-in senders and the worker's egress: a device token or message content in a log or response, a push delivered to a device of another user or of a session that ended, a web subscription endpoint that makes backd call a host or port the realm doesn't allow, a provider credential outside the realm's secrets, or a limit that can be exceeded.
- **Organizations and teams** — a member of one organization who can read, count, change or move a document of another (`_meta.org`, `inOrg`, `hasOrgRole`, `orgClaims`, `/v1/{realm}/_orgs`); a member of a team or holder of a team role who can read or change a document of a team they have nothing to do with (`_meta.team`, `inTeam`, `hasTeamRole`); a team role that can be given, extended or kept beyond what the granting rules and its window say; access that outlives a window or a role that needs a second factor the session lacks; an organization template that runs anything, breaks the sanitizer or reaches addresses other than the requester's; an organization context that tells whether an address belongs to an organization; a template data hook that anyone can make run; a role or capability obtained that the granting rules forbid; a managing role through an open invitation link; an invitation token that works for the wrong person or twice; access that survives a removal.
- **Organization sign-in** — `/v1/{realm}/_auth/orgs/…`, `/v1/{realm}/_orgs/{org}/sso`, `/v1/{realm}/_admin/orgs/{org}/sso`, `org_connections` and an organization's secrets (`backd secret … --org`): a person the connection should refuse (another Workspace domain or tenant, a personal account, an address outside `email_domains`) who gets in; an account linked or taken over by address through a connection; a sign-in begun for one organization (or the realm) that finishes at another's callback; a client secret in an answer, log, audit record, export or function, or readable by anyone; a manager who gives roles on joining beyond what they hold, or whose lost roles leave a connection working; a member a manager removed who rejoins without an invitation; an organization that requires its connection (`sso_required`) that still lets a password, magic link, reset or realm provider in, a requirement a manager can turn on without having signed in through the connection, a session opened through a connection that can change the account's credentials, link a provider or delete or export the account (`sso_session`), or an answer that tells whether an organization or a connection exists.
- **Two-step sign-in, re-authentication and magic links** — `/v1/{realm}/_auth/mfa/…`, `…/_auth/reauth`, `…/_auth/magic-link`: a session obtained without the second factor a user has; a code, recovery code or time step that can be used twice or tried beyond the limits; a re-authentication token that works for another session or after its time; a magic link or code redeemed without the asking app's verifier or twice; an answer that tells whether an address is registered; a second factor or secret in a log or response that doesn't need it; an account taken over through a squatter's credentials.
- **Aggregations and search** — an `_aggregate` or `$search` that counts, groups, ranks or returns something the caller's rules don't let them read, runs a stage, operator or expression a client chose, exposes the stored search language, or can be made to use unbounded time or memory.
- **Reference expansion** — `?expand=` that returns a document the caller's rules don't let them read, tells a missing reference from an unreadable one, exposes a field that was not selected or is hidden by the rules, or is cached or served to anyone but its caller.
- **Metrics endpoint** — `METRICS_ADDR`: anything it exposes that its docs say it doesn't, or a way to reach it from outside.
- **JavaScript client** — `backd-js`: credentials it exposes or sends where it shouldn't.
- **Triggers** — `triggers:` in `collection.yaml`, the dispatcher, `backd triggers` and its admin routes: an input a client can influence, a `_meta.chain` that can be set or dropped to hide or force a loop, a `when` that can reach more than `document`, `before`, `changed()`, `now` and `appConfig` or be made to use unbounded time or memory, a `by` taken for an identity, a job run twice for one change without the function being able to tell, a second dispatcher that can move the position, or an overload that drops events without recording them.
- **Realtime** — `POST /v1/{realm}/_realtime`: an event, id or count that a caller's rules don't let them read, a removal told to someone who couldn't see the document, a resume token usable by another caller or realm or that replays history made while the caller's access was different, a stream that outlives its session, key or role, a subscription filter that reaches more than the allowlisted operators, a system change that reaches clients with more than keys and field names, or buffers and reads that grow without bound.
- **Export and import** — `backd export` and `backd import`, `/v1/{realm}/_admin/export` and `…/import`, packages and their manifest, the one-time export key, direct mode and anonymized exports: a package or archive that makes the CLI read or write outside it, a way to import something the API would refuse, a record, log or response that holds a key, a password or document content, a lease used by someone else, an anonymized copy that keeps what the docs say it removes, or a direct-mode bypass reachable from the network.
- **Password expiry and breach response** — `backd user expire-passwords`, `revoke-sessions`, `notify-expired`, `reset-link` and `expire-password`, `/v1/{realm}/_admin/passwords`, `…/sessions` and `…/users/{id}/reset-link`, the password epoch and `password_expired`: a password, a second step or a session that works after it should not, an answer that tells someone without the right password that it is expired, a reset link or token in a log, the audit trail or a response other than the one that made it, a way to move the epoch backwards, an action that does not need full administration and a fresh proof, or a notification that writes to the wrong person or to nobody twice. `POST /_auth/password/update` is in this area too: it must refuse a password the realm's epoch expired, ask the second factor of an account that has one, count wrong proofs like a sign-in and never start a session.
- **Deployment files** — `deploy/terraform` and `deploy/kubernetes`: a default that opens a port or a host to the internet, puts a secret where it can be read by more than the workload that needs it, weakens the pod or network restrictions the docs describe, or lets the admin host be opened to everyone.
- **Query language** — `where`, `order_by`.
- **In general** — anything that lets a caller read or change data they shouldn't.

Out of scope:

- Realms configured with `auth: disabled`: they are open by design.
- Denial of service through request volume. Rate limiting belongs in the reverse proxy in front of `backd` (see the operations docs).
- Weaknesses in how you deploy it, such as serving without TLS or leaking API keys.

Before exposing backd, go through the [hardening checklist](https://fernandezvara.github.io/backd/docs/operate/checklist/) (Operations → Hardening checklist in the documentation). The security model is under Authentication → Security model, and a tested production reference deployment is in [`deploy/production`](deploy/production) (Operations → Production deployment).

## Consents and personal data

- Consent records are append-only (no route updates or deletes them), keep the SHA-256 of the exact text shown, and hold an IP address and user agent only when `compliance.consent_proof` lists them. At erasure those two are removed and the user id becomes an HMAC of the address under the realm secret `BACKD_CONSENT_PSEUDONYM_KEY`; the records are removed after `compliance.consent_retention`.
- The consent challenge of a sign-in is random, single-use, expires in 5 minutes and is stored only as a hash. After a `reaccept_by` date, a session that has not accepted can only read its consent state, accept, sign out or delete the account.
- Administrators record consents with a required `evidence`, audited. `evidence` should be a reference, not personal data.
- `GET /_consents` serves public texts and nothing about people; the personal data scope report (`/_admin/compliance/scope`) needs the `config` area.
